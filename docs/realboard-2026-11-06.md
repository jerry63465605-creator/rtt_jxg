## 2. B19：15352《布莱切利园》拦截窗口强挂起

脚本：`tools/_realboard_b19_15352.js`

```
✓ 拦截窗口已开出（15352 在候选）
✓ 只有英方视角可见（Axis.armed_offer = null）
✓ 窗口存在时德国 next_phase 被拒：
    「等待【英国】决定是否发动《布莱切利园》（对方时点，不可继续推进）」
✓ 仍停在原阶段
✓ 表态后德国恢复推进：「—— 第 8 回合 · 德国 · 空军阶段 —— | 出牌阶段 -> 空军阶段」
ALL PASS（5 项）
```

**限制（已在脚本里注明）**：窗口不是“德国真的打出一张增强卡”触发的，而是由引擎的
派发函数 `offer_armed_effects('enemy_echo_played', 同款 ctx)` 生成。原因：

- 德国所有 `EFFECT`（增强卡）都是**机会卡**，`play_card` 直接被拒：
  「《JU-87 俯冲轰炸机》不能主动打出 —— 它是「部署或调度空军后…」的机会卡」；
- 想走真实链路（建设海军 → `after_build_navy` → 打出 15208）失败：该快照德国**空军已满（2）**，
  无法再部署空军去满足 15205 的条件；15208 的 `after_build_navy` 窗口在本盘面下候选为空。

→ 结论：**门禁/视图/日志三层已在真盘面上验证**；「触发源」这一段仍是半真实，
脚本已把两条失败链路的原文日志打印出来，便于复现。

## 3. B22：17846《坦克运输》锁定刚建成陆军

脚本：`tools/_realboard_b22_17846.js`

```
✓ 建设完成（北欧/中亚…）
✓ 建设方 view.last_built = {piece_id:'p50', space:中亚, nation:德国, type:army}
✓ 对手视角 last_built = null
✓ 不再报「请选择发起单位」
✓ 也没有「只能以刚刚建成的这支陆军」
✓ 真实结算：
    「【德国】发动《坦克运输》—— 德国 发起陆战：莫斯科 | 【苏联】陆军 从 莫斯科 移除」
ALL PASS（6 项）
```

**限制**：建设步骤用的是 `build_piece` 原子（与《建设陆军》内部同一函数），
因为中局快照 `play_done['德国'] = true`，`debug_set_phase` 也会把它重置回 `true`，
`play_card(15300)` 被拒：「德国 本回合出牌阶段已打出 1 张牌（每回合 1 张）」。
`activate_status` 之后的整段仍是玩家动作。

## 4. 中局快照的三个硬限制（以后写 realboard 脚本必看）

| # | 限制 | 表现 | 绕法 |
|---|---|---|---|
| 1 | `play_done` 六国全 `true` | 任何 `play_card` 都被拒 | 换开局快照，或接受“用原子代替打牌”并在文档标注 |
