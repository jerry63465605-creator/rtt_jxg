# 17846《坦克运输》建设期间失效排查（2026-10-23，game 24）

> 卡面：建设陆军后，弃置 1 张 [建设陆军] 或 [发起陆战]：**以此陆军**发起 1 次陆战。

## 一、日志现场

```
西伯利亚大铁路：已在 德国 建设 1 支陆军，剩余 1 次
【苏联】弃置 1 张手牌                                   ← 代价已付
《坦克运输》效果未能执行：《坦克运输》只能以刚刚建成的这支陆军发起陆战
```

动作记录：

```
#793 resolve_autobahn   { space: 44 }                                  ← 在德国建成
#794 activate_status    { card:'17846#22', space:5, from:'p79', victim:'p69' }
```

对照盘面：

| 项 | 值 |
|---|---|
| 刚建成的陆军 | `p80` @ **德国(44)** ← `status_instant.space = 44` |
| 玩家提交的发起单位 | `p79` @ **巴尔干(12)** |
| 玩家提交的目标 | `space 5` = **东欧**（相邻有德军 `p69`） |
| 校验 | `location[p79](12) !== sp(5)` → 拒绝 |

## 二、根因

客户端选目标地区后，用**通用** `battle_initiators` query 取候选
（= "与目标相邻、处于补给的本国陆/海军"），于是巴尔干的 `p79` 也在列表里，
玩家点了它也能提交。

服务端直到 `run` 里才校验"必须是刚建成的那支"，而 `activate_status`
是**先付代价、后执行效果**：

```js
if (cost.discard) { discard_card(...) }        // 先扣 1 张
...
const r = run_status_effect(...)               // 才发现参数非法
if (!r.ok) { 只记日志 }                         // 代价不回滚
```

→ 效果没发生、手牌白亏 1 张，且窗口保留还能反复点、反复亏。

## 三、三处修改

| # | 位置 | 改法 |
|---|---|---|
| 1 | 17846 配置 | 新增 `precheck(game, nation, arg, ctxSpace)`：付代价**前**校验 `from` 必须是"位于刚建成地区的本国陆军"，失败提示具体地区（"刚建成于 德国"） |
| 2 | `activate_status` | 支持 `tr.precheck`：在 `cost.discard` / `attrition` / `skip_play` 全部之前调用；失败 → **不付代价**、窗口保留、日志带「（未支付代价）」 |
| 3 | `activate_status` 的 `!r.ok` 分支 | 兜底**退回 discard 代价**（从弃牌堆取回放回手牌，日志「已退回 N 张代价手牌」）。损耗/失分/放弃建设卡不回滚（已改变盘面，无法精确还原） |

`precheck` 是可选的，没有该字段的卡行为完全不变。

## 四、game 24 现在怎么操作

第 5 次建设还没做（`pending_autobahn.remaining = 1`）。
发动《坦克运输》时必须用**刚建成的那支**陆军（上次是德国 `p80`），
点错会被明确拒绝且**不扣牌**：

```
《坦克运输》只能以刚刚建成的这支陆军发起陆战（刚建成于 德国）（未支付代价）
```

## 七、回修入口

| 症状 | 先看 |
|---|---|
| 点了状态卡就白亏一张牌 | 该卡 `trigger` 是否该加 `precheck`；`activate_status` 的 precheck 调用是否还在付代价之前 |
| 效果失败后手牌没退回来 | `!r.ok` 分支的退回逻辑；`discard_card` 是否真把牌放进了 `game.discard[costPayer]` |
| 《坦克运输》提示"只能以刚建成的这支" | `status_instant` 的 `space` 是否为最近一次建设地区；客户端是否引导玩家点了别格陆军 |
| 建设期间发动状态卡没反应 | `build_actions` 的 `pending_autobahn` 分支是否仍通过 `register_status_actions` 放行状态卡 |
