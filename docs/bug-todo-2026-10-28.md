## 二、归类（是否一类问题）

### A 类：持续光环（ongoing）的生命周期 —— 压制不生效 / 离场不撤销

**共同根因**：光环写进 `game.status_aura.*` 后是**持久字段**，读取处直接裸读，
不判断「这张卡当前是否还生效」，也无法回溯是哪张卡写的。

涉及 24 张 `ongoing` 卡：

| kind | 卡 |
|---|---|
| `axis_only_seas` | 15254（**已修**：`strait_force_axis` 存 cardId + `status_card_effective`） |
| `always_supplied` | 15346、15356、17838、17849 |
| `supply_point_and_markers` | 15345、15347、15443、17742 |
| `space_immune` | 8601、17539 |
| `home_override` | 15344（free_french）、17554、17845 |
| `pair_adjacency` | 17744、17747 |
| `shared_supply_group` | 17549 |
| 其余 | 6601、15343、15444、16304、17553、17840、17901 |

`revert_status_ongoing` 目前只有 `always_supplied` / `free_french` / `port` / `space_immune` / `axis_only_seas` 五个分支，
**其余 kind 撤销时什么都不做**。

### B 类：触发顺序由「栈 LIFO」隐式决定，而非卡面语义

`request_responses` 把每次命中的卡压成独立栈帧，**后派发的帧在栈顶、先处理**。
于是「先发生的事件，其响应反而后结算」，与玩家直觉相反。

- 已知实例：罗马尼亚增援（piece_removed 先派发）晚于法兰西爱国者（battle 后派发）
- 后果：同名额/同格资源被先结算者占掉，后者永远失败

### C 类：触发时点本身不合适（死时点 / 时机早于状态就绪）

- 15207 `turn_start`：派发在 `active` 重置之前 → 让权基准过期（已用 `rectify_active` 兜底，属治标）
- 16804 `after_land`：**死时点**（全仓无派发点）→ 已于 10-26 修复

### D 类：多目标选择的候选信息不足

候选名只给「兵种@地区」，同格多个**不同国家**的同类单位时名字相同，玩家无法区分。
- 16804 已修（改为国家+兵种，后因改为「消灭触发的那只」而不再需要候选）
- 15316 仍有此问题

### E 类：命名 / 字段口径不一致（技术债，暂无功能影响）

- `piece` vs `piece_id`
- 部分派发点缺 `piece_id`

> 已合并为清单 #5，统一按 §四 的方案处理。

### F 类：日志公开粒度（保密 vs 复盘）

（见 #7）

### G 类：客户端「能点的 ≠ 能成功的」（选择框 / 门禁两侧不同源）

判定同源是本项目反复踩的坑（通用教训 3）：白名单、view.ready、服务端入口三处必须同一判据。
- #8 KV-2 无选择框
- #11 大日本帝国海军无法发动

### H 类：保护 / 还原后的位置归属

免死类效果生效后，单位应回到**原位置**，而不是走「撤退」流程。

### I 类：触发范围 / 发动门禁

状态卡 / 响应卡的触发条件与实际结算不匹配，或代价已付但效果未落地。
- #13 配给的触发范围
- #14 征兵 / 耀武「损耗了牌没触发」
- **#19 17543 雷达的跨阵营门禁**（「被攻击时」必然发生在敌方回合 → 白名单缺 `piece_removed` 导致永远发动不了）

`HIDDEN_CARD_DESC` 用于暗区不写卡名；但玩家为了复盘要求写卡名时，
会把「牌堆顶」等本应保密的信息一并暴露。

### #19 17543《雷达》门禁修复 —— 细节与待办

**症状**：美国海军被攻击（→ 被移除）后，桌面上的《雷达》窗口亮起，玩家点了**永远无效**，日志只写
「不能触发非本方的状态卡」。等价于这张卡**从来没生效过**。

**根因**

```js
// activate_status（rules.js 28879）
if (!borrowed && !CROSS_NATION_STATUS_WINDOWS[tr.window] &&
    delegate_of_nation(owner) !== delegate_of_nation(game.current_nation)) {
    game.log.push('不能触发非本方的状态卡')   // ← 17543 走到这里
    return game
}
```

雷达是「**被攻击时**」的防御性效果，必然发生在**敌方回合**（谁打你，就是谁的行动轮），
`owner = 美国`、`current_nation = 德国` → 恒不相等 → 恒拒绝。
而 `CROSS_NATION_STATUS_WINDOWS` 原来只有 `{ after_ally_battle, build_army }`。

**修复**：常量加 `piece_removed: 1`。该窗口当前**只有 17543 一张**，不影响其它卡。

**已验证（自动化）**

`node tools/_smoke_air_retreat_restore.js` → S11 全部 ok：

| 美国空军撤到不列颠 | ✅ |
| **17543 进入瞬间窗口（`game.status_instant`）** | ✅ |

**⏳ 待实机复验（留作待办）**

### #20 免死响应卡统一入口 `protect_restored` —— 已完成

**背景**：同一件事（还原部队 + 本回合保护）有两套实现。

| | 普通响应（10 张） | 苏联（4 张，原 `su_defense_protect`） |
|---|---|---|
| 还原 | `restore_piece(game, ctx)` | `restore_piece(game, ctx)` |
| 保护 | `register_modifier({ key:'protect', … })` | **直接 `game.modifiers.push(...)`** |
| `turnNation` | `register_modifier` **自动补** `= game.current_nation` | 手工写同一个值（等价但多余） |
| `card:'su_defense'` | 无 | 有 —— **死字段**（全仓无消费方） |
| `type` | `ctx.piece_type` | 硬编码 `'army'` |
| 地区 | `[ctx.space]` 单个 | **`spaces` 数组**（17836 保护两区） |

**唯一实质差异**：保护地区个数。

**改法**：抽唯一入口，删掉 `su_defense_protect`。

```js
function protect_restored(game, ctx, opt) {
    opt = opt || {}
    restore_piece(game, ctx)                    // 内部已含 restore_retreated_airs
    register_modifier(game, {                   // 统一入口，turnNation 自动补
        key: 'protect',
        nation: opt.nation || (ctx && ctx.piece_nation),
        type:   opt.type   || (ctx && ctx.piece_type),
        spaces: (opt.spaces && opt.spaces.length) ? opt.spaces.slice() : [(ctx && ctx.space)],
        untilTurn: game.turn,
    })
    return { ok: true, desc: opt.desc || '该部队本回合不会被移除' }
}
```

| 卡 | 改后 |
|---|---|
| 15330 / 15332 / 15334 / 15337 / 17730 / 17733 / 17735 | `=> protect_restored(game, ctx, { desc: '…' })` |
| 15420 / 15421 / 15436 | `{ … return protect_restored(game, ctx, { desc: '…' }) }`（保留原注释） |
| 17832 / 17833 / 17835 | `{ nation:'苏联', type:'army', spaces:[space_id_of('罗斯')], desc:'…' }` |
| **17836** | `{ nation:'苏联', type:'army', spaces:['西伯利亚','中亚'].map(space_id_of) }` ← **双地区必须保留** |

**为什么值得做**（不只是洁癖）：

1. **本次就因"两套实现"漏过一次** —— B 方案给 10 张响应卡接飞机复原时，苏联 4 张走的是另一个函数
2. 苏联那套**绕过 `register_modifier`**，将来它新增字段（来源追踪、压制判定）会自动漏掉苏联 4 张
3. 死字段 `card:'su_defense'` 会误导后人以为有来源追踪机制

**已验证（`_smoke_air_retreat_restore.js` 72/72）**

| # | 断言 | 结果 |
|---|---|---|
| S9 | 14 张 impl **全部**含 `protect_restored`；`su_defense_protect` 已不存在 | ✅ |
| S14 | **17836 双地区**：西伯利亚陆军被移除并还原后，**中亚的苏陆军也受保护** | ✅ |
