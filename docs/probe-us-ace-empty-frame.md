> 对象：**17509 王牌飞行员帕皮·博因顿**、**16800 艾森豪威尔 / 16801 哈尔西 / 16802 麦克阿瑟 / 16803 尼米兹**

## 2. 为什么"空框"没了（三条防线仍在）

```
is_empty_echo_frame(pe)  在 rules.js 出现 7 次
① view.pending_echo  —— 空框不下发
② build_actions 排他分支 —— 空框不禁用其它操作
③ exports.action 的 finally —— 空框字段真删（附注释「15209《伞兵》卡死」）
```

实测：17509 / 16800 / 16803 打完后 `pending_echo` 均为 `null` 或空框被清，`view.pending_echo` 也为 `null`，`next_phase` 不被冻结 → **不会再有遮罩挡地图**。

## 3. B29（新）：名将系列"要选地区"时，客户端拿不到候选 → 点了没反应

**复现**（16800，其余三张同构）：

```
建设陆军（17500）→ 窗口 after_build_army 开出 16800 ✓
点 16800（不带 space）：
  日志「【美国】《艾森豪威尔陆军上将》—— 请选择一个地区」
  game.pending_echo        = null
  view.pending_echo        = null
  view.pending_ask         = null
  view.armed_offer.cards[] 里没有任何 candidates 字段
  build_actions 也没有 choose/pick 类动作
→ 客户端没有任何可点候选，玩家只能看到一行日志 = “点了没反应”
```

**但带 space 再发一次就正常**：

```
use_armed_offer{card, space:阿拉斯加}
→「在阿拉斯加再建设 1 支美国陆军」→「在 阿拉斯加 建设 1 支陆军」→ 美国陆军 2→3 ✓
```

**根因方向**：16800 的 `run()` 返回 `{ need:'space', candidates: [...] , pick:1 }`，
而通用"需要选择"的持久化/下发读的是 `cands`（或 `options`）字段 → 候选被判空
→ 正好被 §2 的 `is_empty_echo_frame` 守卫当成"脏空框"清掉 → 提示只剩日志。

> 同样的返回形状也出现在 16801（after_battle sea）、16802（after_land）、16803（after_build_navy），
> 因此四张上将在"需要再选一次地区"时都会卡住；**不需要选地区时（候选为空/自动跳过）反而正常**。

**建议修法**：在 armed `run` 返回 `need` 的统一处理处，把 `candidates` 归一化进 `cands`（或反之），
并让 `is_empty_echo_frame` 只在"两个字段都空"时才判空（现在应已如此，但要确认归一化顺序在守卫之前）。

## 4. B30（新）：17509 无合法空军地时，白扣损耗且提示像"未实现"

```
计分阶段打 17509（中太平洋及相邻 10 格全空、无可部署空军的合法地）
日志：【美国】《王牌飞行员帕皮·博因顿》无法执行：……没有任何可执行的效果
牌库 76 → 75（**代价已扣 1 张**）
卡仍在手牌
```

三个问题叠加：
1. **代价白扣**（卡没生效却扣了损耗）；
2. 提示"没有任何可执行的效果"读起来像**未实装**，而非"当前没有合法部署地"；
3. 由于 1，玩家会以为卡坏了/被吃了。

**建议修法**：`steps` 执行前先算"是否有合法目标"，无目标 → 直接返回 `{ok:false, reason:'<中太平洋>及相邻没有可部署空军的地区'}` 且**回滚/不扣 cost**；
顺带把 17509 的 `desc` 与实际日志统一。
