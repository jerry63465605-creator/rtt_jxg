## 3. 本次修复：17901「能点的 ≠ 能成功的」

- **现象**：在<西伯利亚>（或任何非<罗斯>地区）建设陆军后，桌面 17901 仍然 `ready=true`、
  `ready_reason` 为空；玩家点下去 `run` 才回「仅当在<罗斯>建设陆军后发动」——白点一次。
- **根因**：`arm_status_instant()` 只按「窗口名 `after_build_army` + 同阵营持有国桌面卡」武装，
  **不看建设地区**；17901 的 `trigger` 也没有 `ready` 判定。属 17544《丘克群岛》`space_group` 那一类。
- **修法**（2 处，声明式，不写死 id）：
  1. `STATUS_EFFECTS['17901'].trigger` 增 `build_space: '罗斯'`；
  2. `arm_status_instant()` 武装循环内：`build_space` 与本次建设地区不符 → `continue`（**不武装**）。
     窗口不存在 ⇒ `view.table_status.ready` 与 `build_actions` 的 `activate_status` 白名单**自动同源置灰**。
- **回归**：`_real_test_supp_su.js` 25/25；`_smoke_status.js` 20/2（两条失败为**预存**，
  已用"剥掉本次新增过滤的 rules 基线副本"对比确认：15347 计分标记 / 15338 跳过出牌，与本次改动无关）；
  `test_basic_cards.js` 288/9（基线）；`_run_smoke_report.js` →「未登记失败：无」；`node --check` 通过。
