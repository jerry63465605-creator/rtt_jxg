## 2. 逐卡实测

### 16700《一日之狮》（敌方打出[增强卡]时，损耗 1 张：使其无效）

```
布阵：英国手里 15354《加拿大进入动员》（增强卡，计分阶段开始时打出）
      意大利手里 16700（拦截方；牌库 59 张，付得起损耗 1）
驱动：debug_set_phase(英国, scoring) → play_card{15354}
日志：【英国】打出增强《加拿大进入动员》—— 等待【意大利】的拦截应答
      （代价已先付：S1「代价照付」→ 英国手牌 11→9）
拦截：use_armed_offer{16700实例}
日志：【意大利】损耗 1 张牌 | 打出《一日之狮》—— 敌方增强卡《加拿大进入动员》效果无效
断言：窗口开出 ✓　挂起期间效果未发生（加拿大无英军）✓　代价窗口前已付（-2）✓
      意大利牌库 59→58 ✓　加拿大仍无英军 ✓　15354 进英国弃牌堆 ✓　窗口清空 ✓
对照：skip_armed_offer → 「未被拦截，照常结算」→ 加拿大英陆军 + 北大西洋英海军 ✓
```

### 16701《意大利万岁》（出牌阶段开始时：本回合行动 2 次，但只能打出[基本卡]）

```
play_card{16701} → it_viva=true, it_viva_used=0
第 1 次：play_card{17700 建设陆军, 巴尔干} → 成功；play_done['意大利'] 仍为 false（used=1）
第 2 次：play_card{17700, 东欧}            → 成功；随后 play_done['意大利']=true
第 3 次：play_card{17700, 非洲北部}        → 被拒（"本回合出牌阶段已打出 1 张牌"）
非基本卡：play_card{17739 巴尔干资源 STATUS} → 被拒
          「《意大利万岁》生效中：本回合出牌阶段只能打出[基本卡]」
```

> 细节：`play_done` 里同时出现 `'@acted:意大利': true` —— 那是「本回合动过手」的独立记账（`mark_play_acted`），
> 与「名额」分开，正是 16701 能放行第 2 次行动而 `play_start` 类卡仍能被正确置灰的原因。

### 16702《埃塞俄比亚战争后勤》（<北非>建陆军；对<东非>陆战 **或** 在<东非>建陆军）

```
布阵：意大利海军在<地中海>（让<非洲北部>可建：邻接补给中海军）；英国陆军守<非洲东部>

分支 1（choice=0）：play_card{16702, choice:0, spaces:[15,32]}
  → 第 1/2 步完成：在<非洲北部>建设 1 支意大利陆军（停机，等「下一步」）
  → event_step_next{} → 生成陆战预算 event_budget{kind:'land', remaining:1}
  → event_battle{target:非洲东部, from:<北非新建意军>, victim:uk_ea}
      日志：在 非洲东部 进行陆战，移除敌方陆军（英国）
  → event_finish{} → 预算清空、卡进弃牌堆

分支 2（choice=1）：play_card{choice:1, spaces:[15,32]} → 两次 event_step_next
  → <北非><东非> 各 1 支意大利陆军；无战斗预算残留、卡进弃牌堆
```

> 二选一未选时**不落挂起**：`play_card` 只写一行「需先选择要执行哪一项」，
> 客户端要靠 `query('event_targets')` 拿选项（`arg.choice` 随 play_card 一起提交）。

## 3. 本轮新增的 5 条测试手法（意系卡特有）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 拿**事件卡**当"敌方增强卡"喂 16700 → 窗口不开 | 增强卡 = `type:'EFFECT'`（`ECHO_EFFECTS`）；事件卡走 `EVENT_EFFECTS`，不派发 `enemy_echo_played` |
| 2 | 在**出牌阶段**打 15354《加拿大进入动员》被拒 | 它是「计分阶段开始时」的增强卡 → `debug_set_phase(英国, scoring)` 再打；16700 不限阶段，计分阶段同样是真实时点 |
| 3 | 多步 EVENT 打完就断言委托字段 → `delegate=null` | `16702/16703` 都停在「第 1 步完成」，必须 `event_step_next{}` 才执行第 2 步（16703 的委托就在第 2 步） |
| 4 | 事件卡战斗步以为 `event_step_next` 能直接打 | 战斗步只生成 `event_budget`；真正发兵用 `event_battle{target, from, victim}`，收尾用 `event_finish{}` |
| 5 | 用「计分阶段事件卡」验证 16701 的"只能打基本卡" | 那样被拒的原因是**阶段**不是 16701（假通过）；改用**状态卡**（出牌阶段本可打出），拒绝理由才是「《意大利万岁》生效中…」 |
