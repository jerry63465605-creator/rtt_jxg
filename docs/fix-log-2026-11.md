## 2026-11-04 · S1 状态卡"一回合一次"被判空（17848 一回合多次）+ 新增权威字段 `turn_owner`（服务端）

- **症状**：17848《正面攻击》等带 `once_per_turn` 的状态卡，同一国家回合内可以发动多次。
- **根因**（三条叠加）：
  1. `freq_key(game)` 用**瞬时** `game.current_nation` 做键，而让权/委托/战斗挂起会临时改写它 →
     同一国家回合出现两个键 → `status_used[cid] === freq_key` 判空；
  2. `status_used` 记账写在 `run_status_effect` **之后**，而 17848 的 run 会再发起一次陆战，
     那次战斗结束又 `arm_status_instant('after_land')` → 同一张卡在运行途中被重新点亮；
  3. 记账键用动作参数 `cardId`，读侧用桌面实例 id，面/实例不一致时（如客户端回传 `17848`）永远不相等。
- **改法**：
  - **新增权威字段 `game.turn_owner`**：`setup()`、开局结束、国家轮转三处写入；
    `freq_key()` 改为 `game.turn + ':' + (game.turn_owner || game.current_nation)`（旧存档自动回退）；
  - 新增一次性 `game.status_inflight`：`activate_status` 在 `run_status_effect` 前后 `set/delete`，
    `arm_status_instant` 跳过 in-flight 的卡（挡"运行途中被重新武装"，不影响多步卡续跑）；
  - `status_used` 键归一成**桌面实例 id**（`_usedKey`：先精确匹配，再按 face 匹配，最后回退）。
- **验证**：`tools/_real_test_17848_once_per_turn.js` **13/13**
  - A 真实陆战触发 → 武装 → 发动成功，`status_used["17848#75"]="1:德国"`（实例 id + turn_owner）
  - B 同回合再打一场陆战 → **不再武装**（once_per_turn + in-flight）
  - C 强制再发 → 被拒「本回合已经发动过」，牌库张数不变（无白付）
  - D 模拟让权（`current_nation=日本`）→ `freq_key` 不变
  - E `turn+1` 进入下一整轮 → 允许再次发动
  - F 静态守卫 4 条（freq_key / inflight / 写入点）
  - 回归：`_real_test_17543_radar` 33/33（同样用 once_per_turn）、`test_basic_cards` 288/9（与基线一致）、全量冒烟 112 全绿
- **设计文档**：`docs/turn-flow.md` §3.1 新增 `turn_owner` 权威字段说明（语义 / 写入点 / 唯一消费点 / 兼容性 / 6 人模式扩展提醒）
- **提交**：`fix(quartermaster): S1 状态卡一回合一次 —— freq_key 改用回合归属国 turn_owner + in-flight 防重复武装`

## 2026-11-04 · T4 响应选完目标后地图金色高亮不消失（客户端）

- **症状**：响应卡（如 `kind:'space'` / `kind:'piece'` 的目标选择）选完目标后，框消失了，
  但地图上的金色 `.target` 高亮还留着，玩家以为还能点，点了没反应。
- **根因**：`play.js: update_response_choice_box()` 自己贴高亮，但**不在**
  `reapply_all_highlights()` 的每帧重贴名单里；窗口关闭（`!rc`）与 `submit()` 两处都只清
  `ask_box`，没有 `clear_target_highlight()` → 高亮活到下一次其它高亮重贴/整盘重绘才掉。
- **改法**（`play.js`）：
  - 新增 `rc_highlight_active` 标记 + `clear_response_choice_highlight()`：
    清掉 `.target` 后**立刻** `reapply_all_highlights()`，保证只掉"响应那一层"，
    不误伤同帧的战斗预算 / 让权委托 / 建设高亮。
  - `!rc` 分支、`submit()` 里各调用一次；`space` / `piece` 分支贴完高亮后置
    `rc_highlight_active = true`；`card` / `option` 分支置 `false`。
- **验证**：`tools/_dom_test_response_choice_clear.js` **4/4**
  - A `space` 型响应 → `.space.target = 候选数`
  - B 窗口关闭 → `.space.target = 0`
  - C 与 `event_budget` 共存 → 清完响应后预算高亮仍在（= 预算 targets 数）
  - D 点选项 `submit()` → 派发 `resolve_response_choice`
  - 回归：`_dom_test_15209_budget` 5/5、`_dom_test_15209_click` 2/2、
    `_dom_test_15315` 14/14、全量冒烟 112 全绿
- **提交**：`fix(client): T4 响应选完目标后地图金色高亮不消失`；版本串 → `?v=20261104h`

## 2026-11-04 · T3 战斗挂起期间非应答方按钮全亮（服务端）

- **症状**：一场战斗挂起、正等防守方表态时，**非应答方**（发起方）那一侧的
  出牌 / 推阶段 / 换国 等按钮依旧是亮的，点了才被拒；界面也看不出"正在等对方"。
- **根因**：`build_actions_inner(game, side, is_my_turn, pendingBattle, …)` 的
  `pendingBattle` 是**按阵营过滤过的视图字段**（非等待方为 `null`），
  而分支写成 `if (pendingBattle)` → 非应答方直接跳过该分支、落到通用动作表，
  且 `block_reason` 为空。
  （同文件的响应窗口分支早已用 `pendingTrigger || top_response_frame(game)` 兜住真相源。）
- **改法**（`rules.js`）：分支条件改为 `if (pendingBattle || game.pending_battle)`，
  内部用 `pbRaw = pendingBattle || game.pending_battle` 取等待方；非应答方
  只给 `{ log: 1 }` 并写 `block_reason = 'pending_battle: 等待【X】…'`。
  `view.pending_battle` 仍只下发给等待方（保密不受影响）。
- **验证**：`tools/_verify_battle_pending_actions.js` **12/12**
  - A 同盟发起 / 德国防守：Axis `[log, resolve_battle, …]`、Allies `[log]`、block_reason 指向等待
  - B 反向（Axis 发起 / Allies 防守）：方向对调后同样成立
  - C `view.pending_battle` 只给等待方
  - D 应答方表态后两侧动作恢复
  - 回归：`test_basic_cards` 288 通过 / 9 失败（改前改后完全一致，属既有已知项）、
    全量冒烟 112 全绿
- **提交**：`8e1d1e5`

## 2026-11-04 · S1+S2 点「结束《伞兵》」后空框复活并卡死（服务端）

- **症状**：15209《伞兵》点「结束《伞兵》」→ 那个只有「不发动」的全屏空框再次出现、界面卡死。
- **根因**：抑制空框的判据绑在 `game.event_budget` 上；`event_finish` 一清空预算，
  条件失效，存档里那条脏 `pending_echo`（战斗步 `pending` 被误写成 `echo_need`）复活。
- **改法**：新增唯一判据 `is_empty_echo_frame(pe)`（`kind==='echo_need'` 且 `options`/`cands` 皆空）；
  `view.pending_echo` / `build_actions` 排他分支 / `do_action` 冻结门禁三处改用它、**不再依赖 event_budget**；
  并在 `exports.action` 的统一出口（`finally`）`if (is_empty_echo_frame(game.pending_echo)) game.pending_echo = null`
  真删脏字段。
- **验证**：`tools/_verify_15209_finish_recover.js` **11/11** + 既有 15209 三组测试 + 17514 回归 21/21 + 冒烟 112 全绿
- **提交**：`87102a9`

## 2026-11-04 · 显示对齐：fonts.css 路径 + 静态资源版本串 + style.css（平台层）

- **症状**：本地侧边栏字号与线上不同、单位上的符号字缺失；`/join` 页面明显比线上大。
- **根因**：① `fonts/fonts.css` 15 处写死 `/pre/fonts/*.woff2`，本地 404 → 字体全回退；
  ② `play.html` 里 `client.css` / `client.js` / `fonts.css` **没有版本串**，改动后浏览器一直吃旧缓存；
  ③ `public/style.css` 是旧版（缺 `font-size:14px` 等规则）。
- **改法**：① 15 处改相对路径（`SourceSans3-Regular.woff2`）；② 7 处引用统一 `?v=`；③ 用线上版覆盖 `style.css`。
- **验证**：`tools/_verify_fonts_served.js`（23 个字体全 200）、`tools/_parity_check.js` 与
  `tools/_dom_parity.js`（线上/本地资源逐字节一致 + 同一 view 下 DOM 结构一致）
- **提交**：`8b40267`（字体）、`7ded138`（版本串）、`c14408f`（style.css）
