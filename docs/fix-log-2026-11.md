## 2026-11-05 · B2《西班牙控制直布罗陀》改为"海峡强制轴心"（服务端）

- **症状**：17747 打出后，`<北海>`↔`<地中海>` 对**同盟仍然相邻**（卡面是"仅对友方国家相邻"）。
- **根因**（两层）：
  ① `北海↔地中海` 本来就是 **data.straits id=15（def: allies，直布罗陀海峡）**——
     `compute_connections` 会把该 pair 从两岸营移除、再按控制方加回，所以"同盟相邻、轴心不相邻"是海峡控制权的结果；
  ② 17747 只用 `pair_adjacency` 给轴心**加**一条，无法"夺走同盟的通行权"，于是同盟照样相邻。
- **改法**：
  - `axis_only_seas` 支持按【无序对】精确指定海峡（`pairs:[[名,名]]`）；
    旧写法只给地区名 → `straits.find` 命中第一条包含它的海峡（"北海"会误命中北欧 id=4）；
  - `apply_status_ongoing` / `revert_status_ongoing` 支持 `ongoing` 为**数组**（一张卡同时声明多种光环）；
  - 17747 改为 `[axis_only_seas(北海-地中海), pair_adjacency(非洲北部-西欧, only axis)]`；
  - `axis_only_seas` 的提示文案改为按声明生成（不再写死 15254 的北欧海峡）。
- **验证**：`tools/_real_test_17747_strait.js` **16/16**
  A 卡前 同盟 true/轴心 false；B 打出后 **同盟 false/轴心 true**；
  C 与 15254 同时在场 → 只强制 id=4 与 id=15（不再误命中）；D 撤销后同盟恢复、轴心断（pair_adjacency 按设计永久保留）；
  E 非洲北部-西欧 仍只对轴心；F 回归 17744；G 静态守卫 3 条。
  回归：`_smoke_italy_status`（断言已更新为新结构）、`test_basic_cards` 288/9、全量冒烟 112 全绿。
- **提交**：`fix(quartermaster): B2 直布罗陀改为海峡强制轴心（ongoing 支持数组 + pairs 精确匹配）`

## 2026-11-05 · B1《高速公路》/《西伯利亚大铁路》收回陆军时处理载体空军（服务端）

- **症状**：15228《高速公路》把德国陆军全部收回后，原来停在陆军头上的**空军留在原地**（没撤离也没消灭）。

## 2026-11-04 · S1 状态卡"一回合一次"被判空（17848 一回合多次）+ 新增权威字段 `turn_owner`（服务端）

- **症状**：17848《正面攻击》等带 `once_per_turn` 的状态卡，同一国家回合内可以发动多次。
- **根因**（三条叠加）：
  1. `freq_key(game)` 用**瞬时** `game.current_nation` 做键，而让权/委托/战斗挂起会临时改写它 →
     同一国家回合出现两个键 → `status_used[cid] === freq_key` 判空；
  2. `status_used` 记账写在 `run_status_effect` **之后**，而 17848 的 run 会再发起一次陆战，
     那次战斗结束又 `arm_status_instant('after_land')` → 同一张卡在运行途中被重新点亮；
  3. 记账键用动作参数 `cardId`，读侧用桌面实例 id，面/实例不一致时（如客户端回传 `17848`）永远不相等。
- **改法**：
  - **新增权威字段 `game.turn_owner`**：`setup()`、开局结束、国家轮转三处写入；
    `freq_key()` 改为 `game.turn + ':' + (game.turn_owner || game.current_nation)`（旧存档自动回退）；
  - 新增一次性 `game.status_inflight`：`activate_status` 在 `run_status_effect` 前后 `set/delete`，
    `arm_status_instant` 跳过 in-flight 的卡（挡"运行途中被重新武装"，不影响多步卡续跑）；
  - `status_used` 键归一成**桌面实例 id**（`_usedKey`：先精确匹配，再按 face 匹配，最后回退）。
- **验证**：`tools/_real_test_17848_once_per_turn.js` **13/13**
  - A 真实陆战触发 → 武装 → 发动成功，`status_used["17848#75"]="1:德国"`（实例 id + turn_owner）
  - B 同回合再打一场陆战 → **不再武装**（once_per_turn + in-flight）
  - C 强制再发 → 被拒「本回合已经发动过」，牌库张数不变（无白付）
  - D 模拟让权（`current_nation=日本`）→ `freq_key` 不变
  - E `turn+1` 进入下一整轮 → 允许再次发动
  - F 静态守卫 4 条（freq_key / inflight / 写入点）
  - 回归：`_real_test_17543_radar` 33/33（同样用 once_per_turn）、`test_basic_cards` 288/9（与基线一致）、全量冒烟 112 全绿
- **设计文档**：`docs/turn-flow.md` §3.1 新增 `turn_owner` 权威字段说明（语义 / 写入点 / 唯一消费点 / 兼容性 / 6 人模式扩展提醒）
- **提交**：`fix(quartermaster): S1 状态卡一回合一次 —— freq_key 改用回合归属国 turn_owner + in-flight 防重复武装`

## 2026-11-04 · T4 响应选完目标后地图金色高亮不消失（客户端）

- **症状**：响应卡（如 `kind:'space'` / `kind:'piece'` 的目标选择）选完目标后，框消失了，
  但地图上的金色 `.target` 高亮还留着，玩家以为还能点，点了没反应。
- **根因**：`play.js: update_response_choice_box()` 自己贴高亮，但**不在**
  `reapply_all_highlights()` 的每帧重贴名单里；窗口关闭（`!rc`）与 `submit()` 两处都只清
  `ask_box`，没有 `clear_target_highlight()` → 高亮活到下一次其它高亮重贴/整盘重绘才掉。
- **改法**（`play.js`）：
  - 新增 `rc_highlight_active` 标记 + `clear_response_choice_highlight()`：
    清掉 `.target` 后**立刻** `reapply_all_highlights()`，保证只掉"响应那一层"，
    不误伤同帧的战斗预算 / 让权委托 / 建设高亮。
  - `!rc` 分支、`submit()` 里各调用一次；`space` / `piece` 分支贴完高亮后置
    `rc_highlight_active = true`；`card` / `option` 分支置 `false`。
- **验证**：`tools/_dom_test_response_choice_clear.js` **4/4**
  - A `space` 型响应 → `.space.target = 候选数`
  - B 窗口关闭 → `.space.target = 0`
  - C 与 `event_budget` 共存 → 清完响应后预算高亮仍在（= 预算 targets 数）
