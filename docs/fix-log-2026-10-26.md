### 1. 【牌面保密】弃牌 / 抽牌 / 资源再分配不得写卡名

**症状**
`game.log` 是**双方共享**的，但日志把玩家在【暗区】里动了哪些牌逐张写了出来：

- 弃牌阶段：`【德国】弃牌阶段：主动弃置 2 张（《闪电战》、《建设陆军》），本阶段累计已弃 2 张`
- 资源再分配：`【德国】资源再分配：弃 3 张手牌，换取基本卡《发起陆战》`
- 脚本抽牌：`【苏联】抽出 2 张牌：《集结》、《急行军》`

**根因**
三个暗区的牌面信息对**对手不可见**：

| 暗区 | 对手可见度 | 所以 |
|---|---|---|
| 手牌 | 仅本方 `view.hands` | 不写卡名 |
| 本方牌堆 | 完全不可见 | 不写卡名 |
| 本方弃牌堆 | 仅**数量** + **顶层一张**（`view.discard_counts` / `discard_top`） | 不写卡名 |

写卡名等价于把整副剩余牌单摊开 —— 与 10-25 批次 C（`FACEDOWN_DESC`）是同一类问题，只是载体从"桌面暗置牌"扩展到"三个暗区之间的流转"。

**判定口径**（照此区分，防止误伤）
- **不写名**：牌在 牌堆 / 弃牌堆 / 手牌 之间流转（抽、弃、损耗、取回、置顶）
- **照旧写名**：**打出的牌**、**桌面状态卡**、**已翻开的响应卡** —— 它们本来就公开
  （打出动作本身要公开播报；桌面卡任何人都能点开看）

**改动**
新增统一文案源 `HIDDEN_CARD_DESC`（`rules.js`，导出到 `_internal`，与 `FACEDOWN_DESC` 同构）：
`draw(n)` / `discard(n)` / `deckDiscard(n)` / `takeBack(n)` / `leaveInDiscard` / `putOnDeck`。

共改 8 处：

| # | 位置（函数 / action） | 原 → 现 |
|---|---|---|
| 1 | 弃牌阶段 `discard_in_discard_phase` | 列出每张卡名 → `主动弃置 N 张手牌（本阶段累计已弃 M 张）` |
| 2 | 出牌阶段 `discard_one` | `弃置《X》` → `弃置 1 张手牌` |
| 3 | `resource_swap` + `resource_swap` action | 返回值拆 **`desc`**（含卡名，只给本方 toast）/ **`logDesc`**（无卡名，进公共日志）；日志写 `执行资源再分配：弃 N 张手牌换取 1 张基本卡` |
| 4 | 脚本抽牌 `draw_pick_discard` | `抽出 N 张牌：《…》` → `抽 N 张牌` |
| 5 | 7900 竭泽而渔 `discard_pay_pick` | `从弃牌堆将 N 张牌置入手牌：《…》` → `从弃牌堆取回 N 张手牌` |

| 7 | 17555 大萧条的余波 `us_depression_discard` | `美国自选弃置《X》` → `美国自选弃置 1 张手牌` |
| 8 | 17729 卡佩里尼链 | 「随机抽到《X》」「《X》非基本卡」「将《X》置于牌堆顶 / 留在弃牌堆」共 4 处去卡名（牌来自各国自己的弃牌堆） |

### 2. 【17554 重庆国民政府】额外打出后同一回合可再触发 → 跨阵营跳日本错乱/卡死

**症状（玩家原话）**
> 美国出牌阶段打出重庆国民政府，发动国家技能准备打另一张牌，
> 此时可以点击**刚刚打出的**重庆国民政府发动效果；桌上有《抗日义勇军》时会跳到日本并卡死。

**涉事配置**
```js
'17554': { trigger: { window: 'play_start', cost: { skip_play: true },
                      run: recruit_piece(中国, 陆军, 中国西部)
                           + after_card_resolved(美国, '17554') } }   // ★卡
'17553 抗日义勇军（美国 STATUS）': 中国建设或征召后 -> 让权日本（弃 1 手牌 + 损耗 1）
```
17554 是★卡 → 结算后再给一次**美国国家技能**窗口；美国技能 = 损耗 1 张 →
**额外打出 1 张状态卡（不占名额）**。

**根因链**（排查过程与证据见 §三）

| 环 | 事实 |
|---|---|
| ① 额外打出不留痕 | `mark_play_done` 在额外打出通道被跳过（20 余处 `!extra` / `!timing && !extra`）→ `play_done` 为空 |
| ② 窗口被误判为"还没出牌" | `play_start` 判据只读 `play_done` → 刚打出的 17554 `ready = true` |
| ③ 客户端与白名单不同源 | `view.table_status[].ready=true`，但 `actions.activate_status` **没登记**；客户端 6877 行 `el.onclick` 不判 ready 就发动作，服务端 `activate_status` 只查 `status_window_ready`（= true）→ 放行 |
| ④ 后果 | 再结算 → 征召中国陆军 → 触发 17553 → 让权日本；此时技能窗口还挂着抢 `active` → `current_nation='日本'` 却 `active='Allies'` 的错配窗口期 |

**改动（三处）**

| 编号 | 改法 |
|---|---|
| **① 统一记账（根因）** | 新增 `mark_play_acted()` / `play_acted()`：把"本回合执行过出牌动作"与【名额】分开记。**不占名额的通道（额外打出 / 按时机打出）也要记**；`play_done` 一字不改，额外打出依旧不占名额。`play_start` 判据改为「`play_done` 或 `play_acted()`」。清理时机与 `play_done` 一致（`phase_play`）。共 20 处调用点补记账 |

**⚠ 实现取舍（需记住）**
`mark_play_acted` 把标记写在 **`play_done` 同一个对象**里（键 `'@acted:<国>'`），
而不是另起 `game.played_this_turn` —— 因为仓库里 100+ 处测试夹具（及 `phase_play`）用
`play_done = {}` 表达"重置出牌状态"，另起字段会残留（实测已把 `_smoke_status` 的 15348 打挂）。
`play_done` 现存用法全是按国名取布尔、无整体遍历、view 不整体下发，故该前缀不污染既有语义。

### ④ 取消"发动后自动推进阶段"（玩家口径）

**为什么要取消**：旧行为是发动 `cost.skip_play` 的卡后**立刻** `advance_phase` 到空军阶段。
在"桌面有 17553 + 17554 + 17555，手牌还有状态卡，发动 17554"这个局面下实测：

```
①【美国】跳过本回合出牌阶段
②【抗日义勇军】中国征召：让权日本——日本需弃置1张手牌并损耗1张
③【大萧条的余波】美国打出[事件/状态]卡：须自选弃置 1 张手牌
④（17553 让权未决，暂不给美国开国家技能窗口）
⑤【美国】发动《重庆国民政府》—— 中国在中国西部 征召陆军
⑥【美国】跳过出牌阶段 —— 出牌阶段 结束，自动进入空军阶段   ← 两个挂起都还没结算
```

三个副作用：挂起被甩到错误阶段；随后给的额外打出权 `phase='play'` 一离场立刻失效
（"看得见用不了"）；且原实现只检查**响应类**挂起，委托/弃牌类根本不在范围内。

**新行为**：不替玩家推进阶段。"跳过"靠**占掉出牌名额**兑现 ——
`skip_play_done`（既有，供 `status_window_ready` 拒绝再发动）+ `mark_play_done` + `mark_play_acted`。

**改动后实测**：

| 项 | 旧 | 新 |
|---|---|---|
| phase | `airforce` | **`play`**（挂起留在本阶段内） |
| `play_done` | 未置 | `{"美国":true, "@acted:美国":true}` |
| 再打出一张牌 | 阶段已跳走 | 被名额挡住 ✅ |
| 让权 / 17555 弃牌 | 都被甩到空军阶段 | 都在出牌阶段内，两种顺序都能结算（已验证不阻塞） |

**关键前提**：必须补置 `play_done` / `play_acted` —— 否则玩家仍停在出牌阶段却还能继续打牌，
"跳过出牌"的代价就漏了。这正是"记得出牌阶段被占用了、状态改为出过牌"那一点。

**顺带修掉的对象错乱**：日本（被让权方）点 `next_phase` 时，原本会看到
"请先弃置《大萧条的余波》要求的 1 张手牌"—— 那是**美国**的义务。
现在 `next_phase` 在跨阵营让权未决时直接拒绝并给出正确出口：

```
【抗日义勇军】请先处理日本需弃置的 1 张手牌（并损耗 1 张），再推进阶段
```

归还后美国点 `next_phase` 即正常推进（实测 `play` → `airforce`）。

### 7. 【响应栈】同组多张响应卡没有「结算顺序」框 → 发动/不发动都点不动

**玩家现象**
日本建设海军时，《潜艇支援》15423 与《海军特别陆战队》15424（还有《海军空降部队》15425）同时命中。
日志提示「请先在响应框中确认结算顺序」，但**客户端根本不渲染那个框** → 两张卡永远发不出去。

**根因（栈重构留下的缺口）**

| 环节 | 事实 |
|---|---|
| 压栈 | `ordered: _toPush.length <= 1` —— 同组 >1 帧时 `ordered = false` |
| `trigger_response` gate | 要求整组 `every(f => f.ordered)`，否则拒绝并提示「请先在响应框中确认结算顺序」 |
| `view.pending_trigger` | 只读**栈顶单帧**，`candidates` **恒为 1 张** |
| 客户端 `update_pending_trigger_box` | `multi = candidates.length > 1 && !ordered` → **永远 false** → 只渲染「发动 / 不发动」，从不渲染排序框 |

于是 `response_confirm` 永远发不出去 → `ordered` 永远 false → 死锁。
更糟：gate 横在 `trigger_response` 与 `pass_response` **之前**，连「不发动」都被拦，玩家没有任何出口。

**四处改动**

| # | 位置 | 改动 |
|---|---|---|
| 1 | 新增 `response_group_frames(game, frame)` | 取同 `group_id` 的全部帧、按 `group_idx` 排序；`group_id` 为空时返回单帧 |
| 2 | 新增 `response_group_ordered(frames)` | **单帧组**（含 defer 搬走兄弟帧后只剩一帧）**视为已确认** —— 否则那一帧自己还是 `ordered:false`，永远发不出去 |
| 3 | `view.pending_trigger` | 「待发动」阶段下发**整组**候选（`candidates` / `order` / `ordered` 全按整组算）；「选目标」阶段仍单帧（由 `response_choice` 驱动） |
| 4 | gate 三处 | `trigger_response` / `response_confirm` / `response_reorder` 全改走上述 helper；且「先确认顺序」**只拦发动**，`pass_response` 放行 |

> **为什么必须同源**：`view` 下发的组必须等于 gate 校验的组，否则又是"看得见 ≠ 点得动"。

**边界（防过严 / 防死锁）**

- **单卡触发不弹排序框**，直接发动。
- 未确认顺序时点「发动」**仍被拦** —— 不许绕过玩家排的顺序。
- 未确认顺序时点「不发动」**放行**（整组放弃）—— 保留逃生口，避免 UI 异常时彻底卡死。
- `defer_remaining_group_frames` 把兄弟帧搬进延期栈后只剩单帧时，视为已确认，不再卡。

**验收**：`node tools/_diag_15423_group_deadlock.js` → **15/15**

| 断言 | 结果 |
|---|---|
| 3 张同点时 `pending_trigger.candidates` = 3、`ordered = false` | ✅ |
| 客户端 `multi = true`（会弹排序框） | ✅ |
| 未确认时发动被拦；确认后发动成功，3 张按 `order` 依次结算 | ✅ |
| 两张（玩家报的组合）同样修复 | ✅ |
| 单卡不要求排序、可直接发动 | ✅ |
| 未确认也能「不发动」并清空该组 | ✅ |
| 剩单帧视为已确认、可直接发动 | ✅ |

**回归**：全量 **15 项失败断言 / 28 项退出码非 0，与基线逐项一致，零新增**。

### 13. 【免死卡 × 空军撤退】不代受撤走的飞机救不回来（10 张卡）

**症状（玩家原话）**
「免死的飞机撤退时，发动后飞机应**回原处**而不是撤退。」

**根因**

空军在防守方「不代受」时会从战斗地区撤离，这段代码只改 `location`，**不派发任何事件**：

```js

    if (retreatTo != null) game.location[a] = retreatTo   // 撤到邻区
    else { delete game.location[a]; retreatRemoved.push(a) }  // 无处可撤 -> 删除
}
```

`retreated_airs` 早在 `piece_removed` 的 ctx 里传了（`retreated_airs: guardAirs.slice().sort()`），
但当时**只有 15334《驱逐舰》**在 impl 里内联消费它（9 行），其余 9 张免死/还原卡
（15330 / 15332 / 15337 / 15420 / 15421 / 15436 / 17730 / 17733 / 17735）完全没读 ——
于是「被移除的那支部队」能救回来，「被迫撤走的飞机」留在撤退地或凭空消失。

**改法**

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增原子 `restore_retreated_airs(game, ctx)`（`restore_piece` 之后） | 把 `ctx.retreated_airs` 逐支拉回 `ctx.space`；**无处可撤被删除的也复活**（`piece_nation` 未清理，补回 `location` 即可） |
| 2 | 10 张卡的 impl 统一加一行调用 | 15334 的内联 9 行改为调原子，口径统一 |
| 3 | `victimProtected` 时不撤退空军（方案 b） | 旧行为：目标受保护仍照常撤退，且受保护分支**不派发** `piece_removed` → 飞机白撤且无窗口可救 |

**与 `restore_piece` 的分工（写测试时最容易混）**

| 函数 | 救谁 |
|---|---|
| `restore_piece(game, ctx)` | **victim**（被移除的那支部队） |
| `restore_retreated_airs(game, ctx)` | **retreated_airs**（同场因不代受撤走的其它空军） |

if (mine[nat] && !in_supply[pid]) {        // ← aura 部队 in_supply 已为 true，整段被跳过
