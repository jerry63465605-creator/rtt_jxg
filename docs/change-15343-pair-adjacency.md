# B25-c：17744 / 17747 的「成对邻接」也能被 15343 压制；B25-b 评估结论：不改

> 日期：2026-11-06　范围：`rules.js`（3 处）　相关卡：15343 霍巴特滑稽坦克 / 17744 土耳其开放海峡 / 17747 西班牙控制直布罗陀

## 1. 问题（B25-c）

两名意大利状态卡给轴心**加**永久成对邻接：

| 卡 | 邻接 | 实现 |
|---|---|---|
| 17744 土耳其开放海峡 | `<黑海>-<地中海>`、`<巴尔干>-<中东>` 仅对友方（轴心）相邻 | `game.status_connections.push({a,b,side:'axis'})` |
| 17747 西班牙控制直布罗陀 | `<非洲北部>-<西欧>` 仅对友方相邻 | 同上（另有一条带直布罗陀海峡，走 `strait_force_axis`，已由 B25-a 修复） |

这些记录**不带卡 id**，读取处（`get_connections`）只按 `side` 过滤 → 英国回合里挂着 15343
（敌方状态卡无效），英美照样能走 `<黑海>-<地中海>` 等邻接。

## 2. 修法（3 处）

```js
// ① 写入带卡 id（rules.js:8655）
game.status_connections.push({ a: a, b: b, side: onlyF, card: card_id })

// ② 读取按有效性过滤（rules.js:407）
if (sc.card && !status_card_effective(game, sc.card)) continue   // 15343 / 15353 压制时跳过

// ③ 卡离场按 card 摘除（revert_status_ongoing 的 pair_adjacency 分支）
game.status_connections = game.status_connections.filter(x => x.card !== card_id)
```

- 老存档没有 `card` 字段 → 视为常驻有效，**行为不变**；
- 顺带把“卡不会离场、不实现撤销”这个历史妥协补上了（15328 弃置后邻接会一起消失）。

> 语义提醒：17744 是“给轴心**加**一组邻接”，不是“夺走同盟的邻接”。
> 所以压制后的正确表现是 **轴心失去**这组邻接，同盟本来就没有（评估断言时别写成“同盟恢复”）。

# B25-b 评估结论：**不改**

涉及卡：**15444 丘克群岛**（`port_as`：`<硫磺岛>` 视为日本港口）、**8601 远东共和国**（`space_immune`：`<海参崴>` 日本陆军不因补给移除）。

## 5. 为什么不改

决定性前提：**15343 只在「英国回合」生效**（`status_active` 的 `current_nation === '英国'` 口径）。

| 卡 | 光环用在哪 | 是否落在英国回合 | 结论 |
|---|---|---|---|
| 15444 港口 | ① 日本**建设海军**（日本回合）② 日本**海军补给判定** ③ 计分加分（走 `auto`→`status_active`，**已压制**） | ①② 在日本回合；只有“英国回合里英国打日本海军、顺带算日本海军补给”这一种边角场合 | 收益极低 |
| 8601 免移除 | ① 日本**补给阶段**移除判定（日本回合）② 苏联**计分阶段**失分（苏联回合） | ❌ 两边都不在英国回合 | **实际零影响** |

技术上也不难（把人 `port_as[sp] = 国名` 改成 `{card, nation}`、读取处判一次），但：

1. 需要老存档兼容/迁移，改动面比 B25-c 大；
2. 生效窗口不重叠 → 玩家几乎不可能观察到差异；
3. 唯一真实场景是“英国回合逼日本海军断补”，目前没有卡会造成这种判定。

**结论**：登记为“已评估，不改”。若将来出现能在英国回合触发日本海军补给判定的卡，再连同 `port_as` 的存储改造一起做。
