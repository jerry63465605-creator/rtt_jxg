## 一、口径（玩家 2026-10-25）

> 「只对 XX 提供补给 / 只对 XX 的补给点」（如 15345 / 15347 / 15443 / 17845 / 17554）代表：
> 1. 该地点**现有的所有计分标记**改为「只对 XX 生效」；
> 2. **此后此地添加的计分标记**也只对 XX 有效；
> 3. 其余（没有这种声明的地点）计分标记一律**通用**（谁占谁得）；
> 4. 15233 / 17725《掠夺》不区分归属 —— **现有实现可行，不动**；
> 5. D 组（PRELUDE 5 张）本轮跳过。

由此得出一条铁律：

**「标记归属」是【地点级属性】，不是"加标记时给那一张贴的标签"。**

| # | 通道 | 归属怎么定 | 卡 |
|---|---|---|---|

三条硬伤：
- 通道 1/5/6 给"通用标记"错误地贴上了国家标签（B 组 8 张）；
- 通道 2/4 **只给"本次新增的那几个"贴标签**，没有"改写现有全部"这一步；
- 没有任何一处记录"此地此后都归 XX"，所以后续新增标记不会继承。

## 三、新设计

### 3.1 数据结构（新增一个地点级字段）

```js
game.marker_only = { '<space_id>': '苏联', ... }
```

与 `add_supply_point(sp, onlyN)` 同源：补给点的"仅对 XX" 与 标记的"仅对 XX" 是**同一句卡面的两面**，共用一个声明。

### 3.2 三个入口（取代现有散落调用）

| 函数 | 语义 |
|---|---|
| `set_space_marker_owner(game, space, nation)` | ① 写 `game.marker_only[space] = nation`；② 把该地**现有全部**标记改成 `owner=nation, faction=faction_of_nation(nation)` |
| `add_marker(game, sp, n, owner, faction)` | 内部**先查 `game.marker_only[sp]`**：有则覆盖 `owner/faction`；无则按传入（B 组一律传 `null` = 通用） |
| `remove_marker(game, sp, n, owner, faction)` | 不变；掠夺 / 焦土按口径传 `undefined`（不筛选） |

> `set_marker_owner`（改现有标记）保留为内部实现，被 `set_space_marker_owner` 调用；**卡配置不再直接调用它**。

### 3.3 卡配置统一写法

```js
markers: [
	{ space: '西伯利亚', delta: +1, only: '苏联' },   // 有 only -> 走 set_space_marker_owner
	{ space: '莫斯科', delta: -1 },                   // 无 only -> 通用增减
]
```

单一执行器处理（含日志、UI），卡代码禁止直写三个 API。

## 六、验收

1. 打 15347 后：东欧 2 个标记全 `owner=英国`（含原本那个无主的）
2. 未打任何 A 组卡时：共青城在某地加的标记 `owner=null`
3. 焦土后再在同一地加标记 → 新标记 `owner=苏联`
4. 敌方占领有通用标记的地区 → 能拿到全部分
5. 计分链无需改动（`marker_applies_to` / `allocate_space_score` 只认 `mk.owner`）→ 回归风险低
