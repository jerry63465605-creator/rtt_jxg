## 2. 兵种与地形的对称结构（核心）

修正后，两张战斗卡的差别**只在目标地形**，发起单位完全一致：

| 卡名 | 发起单位 | 目标地形 | 典型场景 |
|---|---|---|---|
| 发起**陆战** | 本国**陆军或海军** | **陆地** | 陆军常规进攻；海军两栖登陆 |
| 发起**海战** | 本国**陆军或海军** | **海域** | 海军海上交战；陆军岸防炮击 |

```
             目标 = 陆地        目标 = 海域
陆军发起      常规陆战          岸防炮击
海军发起      两栖登陆          常规海战
```

**实现上**：`do_battle(game, nation, space, target_piece, kind)` 的 `kind`
只决定目标地形校验，不再限制发起兵种（`army` 或 `navy` 均可）。

### 2.1 建设的地形规则

| 兵种 | 允许的地形 | 相邻要求 |
|---|---|---|
| 陆军 / 空军 | 陆地 | 本国大本营 **或** 邻接**处于补给状态的同国部队** |
| 海军 | **海域** | **置于该海域的新海军将处于补给状态**（= 邻接处于补给状态的本国部队 + 邻接本国或友军陆地部队） |

> 建设还要满足「单位共存」约束：同格位不能有敌方部队，
> 每国每格最多 1 个单位 + 1 个飞机。详见 **`docs/unit-coexistence.md`**。
>
> 攻击还受「目标必须纯敌方」限制（见同一文档）。
>
> **v2.2 注意**（2026-09-22 easy_rule 第五章对齐）：建设海军口径已从"邻接本国陆军"
> 改为"新海军将处于补给状态"——实现上是在 `can_build_at` 里模拟放置后跑一遍
> `compute_supply` 判定，同时覆盖第五章 c)（邻接处于补给状态的本国部队）与
> d)（新部队将会处于补给状态）两条。

## 4. 建设与战斗的实现

### 4.1 `can_build_at(game, nation, space, type)`

```
type = 'navy'  -> 要求 terrain === 'sea'
type = 'army'  -> 要求 terrain === 'land'
                  且（本国大本营 或 邻接处于补给状态的同国部队）
始终要求：该格位无敌方部队
```

### 4.2 `do_battle(game, nation, space, target_piece, kind, opt)`

```
kind = 'land' -> 目标必须是陆地
kind = 'sea'  -> 目标必须是海域
要求：目标格位不能有任何我方阵营单位（必须是"纯敌方"或空地）
要求：目标格位【或相邻格位】有处于补给状态的同国陆军/海军
效果：移除 1 支敌方部队（由 target_piece 指定）
      若目标地区【无人占领】-> 空打：不移除任何单位，但照常占掉出牌机会
opt（easy_rule 七）：
      opt.defend_air  = 防守方用【同地区同国空军】代替受创（原目标留下）
      opt.counter_air = 发起方移除 1 支【相邻本方空军】抵消上面的代替
                        （抵消后原目标照常被移除，双方各损失 1 支空军）
      两者都省略时行为与以前完全一致（直接移除 target_piece）

【两阶段挂起】(2026-09-23 恢复 counter_air)：
  空军介入现在是【两个回合的问答】，不是一次性的 opt：
    ① stage='defend'  等防守方决定是否用空军代受
    ② stage='counter' 防守方已决定代受后，等发起方决定是否抵消
  详见 docs/air-combat.md（代受 + 抵消的完整规格）。
```

### 4.2.1 空打（2026-09-22 规则确认）

| 项 | 结论 |
|---|---|
| 能否攻击无人占领的地区 | **可以**（陆战打陆地空地，海战打海域空地） |
| 效果 | **不移除任何单位**；目的只是打出卡牌、触发其他卡牌效果 |
| 地形限制 | 与打有敌军的地区**完全相同** |
| 出牌机会 | **照常占掉**出牌阶段的三选一（只有"触发条件时可免费打出"的牌才不占） |
| 相邻发起单位 | 仍需相邻格位有处于补给状态的本国陆/海军 |
| 指定 `piece` | 空地没有可移除目标，指定 piece 会被拒绝且不占出牌机会 |

实现要点：`do_battle()` 在敌人列表为空时不再返回错误，而是返回
`{ ok:true, removed:null, empty:true }`；`basic_targets()` 对无守军地区的
`reason` 写作「空地（无守军，可空打）」，客户端照常高亮。

### 4.3 《空军力量》三选一

| mode | 说明 |
|---|---|
| `deploy` | 部署空军：在本土或邻接补给部队处放 1 支空军 |
| `seize` | 夺取制空权：移除目标地区敌方空军，把本国空军移过去 |
| `move` | 调度空军：移到本国陆/海军所在地（也可用弃牌方式免费调度） |

## 5. 出牌阶段：三选一（v2.3，无行动点）

`PHASES[1]` 由旧的 `reset`（收取行动点）改为 **`play`（出牌阶段）**：

| 选项 | action | 说明 |
|---|---|---|
| ① 打出 1 张手牌 | `play_card` | 基本卡走选目标流程；其余卡效果待实现 |
| ② 弃置 1 张手牌 | `discard_one` | 卡进弃牌堆，无其它效果 |
| ③ 减 1 分 | `minus_score` | 本方阵营总分 −1（手牌为空时只能选这项） |

实现要点：

- `game.play_done[nation]` 标记本回合是否已行动，`phase_play()` 进入阶段时清零；
- `check_play_phase()` 被三个 action 共用，已行动则一律拒绝；
- **空军阶段**打《空军力量》/弃牌调度空军**不受**该标记限制（属于空军阶段的独立选择）；
- 旧的 `discard_for_point`（弃 1 张换 1 点）已删除。

### 5.1 资源再分配（`resource_swap`）

```
弃 3 张手牌 → 从牌堆中挑 1 张【基本卡】置入手牌 → 洗混牌堆
arg = { discard: [3 个手牌 id], take: 牌堆中的基本卡 id }
```

- **每个回合各一次**（2026-09-22 玩家修正）。`phase_resource()` 在进入资源再分配
  阶段时把 `game.resource_swaps[nation]` 清零，因此**下一回合（下一轮）会重新可用**；
  同一回合内第二次则被拒。`view.can_resource_swap` 供 UI 禁用按钮；
- 代价是 **3 张不同的实体牌**：同一个实体牌不能重复充当多张代价，
  但**同名**的不同实体牌可以（3 张同名牌合法）。详见下面「卡牌实例化」；
- `deck_basics` 查询返回牌堆中的基本卡供 UI 挑选（返回的是**实体牌**）；
- `shuffle_deck()` 用递增的 `shuffle_count` 保证确定性（同 seed 可重放）。

### 5.2 卡牌实例化（区分「同一张牌」与「同名牌」）

卡组数据里每张卡只有一个 id，同名卡同名 id，但实体牌是多张。若直接用 card_id
当身份，`[x, x, x]`（同一张牌填 3 次）与「3 张同名牌」就无法区分。
因此 `init_nation_deck()` 会给牌堆里的每张实体牌编号：

```
<card_id>#<n>       例：15327#1、15327#2
```

| 函数 | 作用 |
|---|---|
| `inst_card_id(instance_id)` | 去掉 `#n`，取回牌面 id |
| `inst_card(instance_id)` | 取牌面数据（替代 `CARD_BY_ID[x]`） |
| `inst_pub(instance_id)` | 整理成 UI 形状（`id` 是实例 id，另带 `card_id`） |

配套改动：

- `hand_view()` / `view.hands[n].cards` / `view.table_cards` 返回的都是**实体牌**，
  `id` 是实例 id，客户端原样回传即可；
- `play_card` / `discard_one` / `air_support` / `resource_swap` 的 `card`、`take`
  都按实例 id 解析（`resolve_basic_card`、`purge_basic_cards` 亦同）；
- 因此资源再分配的代价去重**按实例 id**：`[15327#1, 15327#1, ...]` 被拒绝，
  `[15327#1, 15327#2, 15327#3]` 允许。

## 6. 客户端交互流程

### 6.1 基本卡选目标

```
点手牌中的基本卡
  └─ send_query('basic_targets', {card_name, mode?})
       └─ on_reply 收到合法目标
            └─ 地图高亮可选地区（金框 + 光晕）
                 └─ 点地区 → send_action('play_card', {card, space, piece?, mode?})
```

**取消**：右键 / Esc / 再点同一张卡。
**《空军力量》**：先弹出三个模式按钮（`#mode_chooser`），选完再进入选目标。

### 6.2 战斗的两步询问（`#ask_box`）

战斗目标里带 `airs`（同地区同国空军）时，先在 `#ask_box` 问防守方是否空军代受；
选了"代受"后再 `send_query('counter_airs', {space})` 问发起方是否抵消；
最后一并提交 `{piece, defend_air?, counter_air?}`。

### 6.3 收回本国部队

| 时点 | 交互 |
|---|---|
| 自己回合内任意时刻 | 直接 `send_action('remove_piece', {piece})`（或从询问面板点） |
| 友方出牌回合开始 | `view.pending_ask` 有值才弹询问；`#btn_toggle_ask` 控制开关，**默认关闭 = 跳过** |

关闭时 `prepare_remove_ask()` 直接返回 null、不挂起任何询问，符合"该时点默认跳过"。

### 6.4 已知 UX 取舍

资源再分配阶段点手牌是"选代价"（最多 3 张，`.sel` 高亮并上浮），需先点
`#btn_resource...` 进入挑选模式，因此不会和"打牌"混淆；确认后收起面板、按钮变为
「本回合已用」并禁用（每回合只一次）；出牌阶段已行动后手牌加 `.disabled` 置灰。

### 6.5 手牌点不中的坑（已修）

`main` 是 `client.js` 的 `transform: scale()` 缩放层，手牌区在地图**下方**，
未占位时命中区域会被 `#mapwrap` 吃掉，表现为"能看见但点不中"。修法：

- `.panel-list { position: relative; z-index: 50 }` 抬高整块面板；
- `#hand_cards .card { pointer-events: auto }` + `#hand_cards .card img { pointer-events: none }`
  保证卡内图片不吞事件；
- 具体动作统一存在 `d.__act` 上，由 `build_card_elt()` 里的 `click` 监听调用，
  不再散落 `onclick`（少一处漏绑就整张卡失效）。

## 7. 三个 RTT 契约坑（务必遵守）

**1. `send_query(q, param)` 的第二个参数是查询参数，不是回调。**

```javascript
// ✗ 结果不会通过 cb 返回
send_query("basic_targets", c.name, (r) => { ... })
// ✓ 结果走全局 on_reply
send_query("basic_targets", { card_name: c.name, mode: "deploy" })
```

**2. `exports.query` 有第 4 个参数 `params`。**

```javascript
RULES[title_id].query(state, role, q, params)   // server.js 的实际调用
```

**3. 同一文件里【只能有一个】`on_reply` 定义。**

函数声明重复定义时**后者静默覆盖前者**，且不报错。
排查方式：`on_reply.toString()` 看实际生效的是哪个。

## 9. 数据陷阱

**1. `data.js` 字段名是 `home_base`，不是 `home`。**

标定文件用 `home`，编译后改名。写成 `sp.home` 会静默返回 `undefined`。

**2. 卡名以 `cards.js` 为准。**

实际是《发起陆战》《发起海战》。用 `switch (c.name)` 分派时必须完全一致：

```javascript
CARDS.filter(c => c.type === 'BASIC').map(c => c.name)
```

**3. 不列颠是岛国，只邻接北海（无相邻陆地）。**

写测试用例时若假设"不列颠有相邻陆地"会失败。陆军测试请用**西欧**等有陆地邻居的点。
