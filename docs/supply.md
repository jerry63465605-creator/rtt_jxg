# 补给系统（Supply）

> 版本 v1.0 · 2026-09-22 · 状态：**已实现并测试通过（36 项）**

---

## 1. 规则原文（简化规则书 第三节）

> **补给**：在游戏过程中，部队可能因为推进过快、被敌军包围或海上封锁而陷入补给不足的状态。
>
> - **陆军**满足以下条件之一，则处于补给状态：
>   - 位于补给点（地图上标记 **★** 的地区）
>   - 与处于补给状态的**本国**部队相邻
> - **海军**满足以下**全部**条件，则处于补给状态：
>   - 与处于补给状态的**本国**部队相邻
>   - 与**本国或友军**的陆地部队相邻

结算（第二节第 4 条）：

> **补给阶段**：将**当前回合国**不处于补给状态的部队移除

---

## 2. 已确认的实现口径（2026-09-22）

| # | 问题 | 决定 | 理由 |
|---|---|---|---|
| 1 | 陆军链条的"本国" | **同一国家**（德只能靠德续接） | 严格照原文；意大利部队不能给德国部队续补给 |
| 2 | 海军第 1 条的"本国" | **严格本国** | 照原文 |
| 3 | 海军第 2 条的"陆地部队" | **本国或友军**（同阵营即可） | 原文明确写了"或友军" |
| 4 | ★补给点归属 | **任一方都能用**，不需驻守 | 只要部队站在★上就处于补给 |
| 5 | 断补结算 | **立即移除**（补给阶段） | 照原文，无宽限 |
| 6 | 结算范围 | 只移除**当前回合国**的断补部队 | 按国家分别结算，非一次性清场 |

### 2.1 关键推论

- **补给链不跨国家**：德军补给线只能由德军续接。日意部队无法帮德军补给。
- **海军需要"有人接应"**：孤立在海上的海军即使邻接友好海域也断补，
  必须有**本国且已补给**的部队相邻（第 1 条），
  且**本国或友军**的陆军相邻（第 2 条）。
- **★是绝对起点**：站在★上的任何部队都是补给源，不受国籍限制，
  也不需要友军接应。这是链条的种子。

## 3. 算法：不动点迭代

### 3.1 为什么不能直接 BFS

`"与处于补给状态的部队相邻"` —— **"处于补给状态"本身就是要求解的结果**。
这是递归定义，不是从种子出发的单向传播。

用普通 BFS 会得到错误结果（按照遍历顺序而非逻辑收敛）：

```
德国(★) — 东欧 — 罗斯
   ↑ 若 BFS 先访问罗斯（那时东欧还没判定），罗斯会被误判为断补
```

### 3.2 正确做法

```
种子：站在★上的所有部队 -> in_supply = true
循环：
    对每个【尚未】判定为有补给的部队：
        陆军：存在邻居格位上有【同国且 in_supply】的部队 -> 标记有补给
        海军：存在邻居格位上有【同国且 in_supply】的部队（第1条）
              且 存在邻居格位上有【同国或同阵营】的陆军（第2条）
              -> 标记有补给
    若本轮无新增 -> 退出（达到不动点）
```

复杂度最坏 O(n²)，但部队数上限约 40-60，实测 **0ms**。

### 3.3 实现

```javascript
compute_supply(game, conn_snap)   // 纯函数，不改 state，返回 { in_supply, sources }
```

- `conn_snap` 可复用 `compute_connections()` 的结果，避免重复计算
- `sources[piece]` = `'base'`（站在★）| `'chain'`（经链条传播）
- 用 `guard < 200` 防死循环（实测收敛很快）

**注意**：与 `get_connections(game, s, side)` 联动 —— 连通性本身受
海峡控制权影响，所以补给的传播路径是**阵营私有**的：
海军只能走本方可用航道，这正是规则想要的效果。

## 4. 断补结算

```javascript
resolve_supply(game, nation)     // 移除该国的断补部队，返回被移除的 id 列表
```

结算后**必须 `refresh(game)`**：部队位置变了，海峡控制权和连通性都可能变。
实测用例：英国陆军孤悬北欧（夺取丹麦海峡）→ 断补被移除 → 海峡控制权
自动回到默认（轴心）。

## 6. 测试

```powershell
node tools/test_supply.js      # 36 项
```

覆盖：
- ★上的部队自动有补给（来源标记 `base`）
- 陆军链式传播（德国→东欧→罗斯→西伯利亚，三级传递）
- **链条不跨国家**（意大利陆军邻接德国陆军不得补给）
- 链条中断则后方全部断补
- 海军两条条件（缺任一即断补）
- 海军第 2 条允许友军陆军
- 断补结算只移除指定国家的部队
- 结算后海峡控制权同步刷新
- 三角循环不死锁（实测 0ms）
- view / query 接口字段

> **测试踩坑**：写用例时误用了两个点导致假失败 ——
> **夏威夷是★补给点**（不能用作"断补"用例）、
> **巴尔干邻接德国(★)**（不能用作"链条中断"用例）。
> 合适的断补测试点是**非洲南部 / 非洲东部**（邻接均非★）。

## 7. 12 个补给点

```
不列颠、西欧、莫斯科、意大利、中国东部、美国、
印度、澳大利亚、德国、乌克兰、日本、夏威夷
```

（由 `out/spaces_calibrated.json` 的 `supply: true` 标定，
经 `tools/gen_module_data.js` 编译进 `data.js` 的 `space.supply`）

> **补给点是静态的还是动态的？** 见专门文档 `docs/supply-points.md`。
>
> 现状：**完全静态**（`data.supply` 编译期常量，无运行时修改机制）。
> 但玩家 2026-09-23 明确：部分地区（波兰=东欧等）初始不是补给点，
> **可被卡牌效果变为补给点，或变为不是**。
> 本文档描述的补给**链算法**不受影响（它只消费 `is_supply_point` 的结果），
> 但补给点本身的判定需要动态化。
