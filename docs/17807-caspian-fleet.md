# 17807《里海舰队》候选地区修复（2026-10-23）

> 卡面：**计分阶段开始时：在 `<里海>` 相邻地区征召 1 支陆军。**

---

## 一、问题

原配置把候选**写死**成两个地区名：

```js
steps: [{ op: 'recruit', type: 'army', spaces: space_ids_of(['中亚', '中东']) }]
```

但 `<里海>`（id 11，海域）的**几何相邻陆地实际有 3 个**：

| 地区 | id | 地形 |
|---|---|---|
| 中亚 | 10 | land |
| 中东 | 16 | land |
| **乌克兰** | 45 | land |

→ **漏了乌克兰**：卡面说"相邻地区"，但玩家在乌克兰无法征召。
`get_connections` 按阵营视角算出来也是这 3 个（里海无海峡限制），所以不是连通性差异。

---

## 二、修法

改成 `spacesFn` 动态计算：

```js
'17807': {
	name: '里海舰队', actor: '苏联',
	steps: [{
		op: 'recruit', type: 'army',
		spacesFn: (game, actor) => {
			const cas = space_id('里海')
			if (cas == null) return []
			return get_connections(game, cas, faction_of_nation(actor || '苏联'))
				.filter(id => (data.spaces[id] || {}).terrain === 'land')
		},
	}],
},
```

- `get_connections` = 阵营视角（与点击判定同源，含海峡规则）
- 地形过滤 = 只要陆地（征召陆军）
- 后续由 `event_cands_filter` 按 `can_recruit_at` 过滤空位（该格有部队则不出现）

---

## 三、验证（实测）

| 项 | 结果 |
|---|---|
| `spacesFn` 返回 | 中亚 / 中东 / **乌克兰** |
| `event_card_needs` candidates | `[10, 16, 45]` |
| 乌克兰已有苏军 | 候选变 `[10, 16]`（自动剔除） |
| 乌克兰有德军 | 同样剔除 |
| 三地全占 | `need` 退化为 null（不再要求选地区） |

## 四、同类扫描结论

扫了「卡面文本含"相邻"、但配置用固定 `spaces`」的全部 EVENT/EFFECT 卡，**只有 17807 是真漏项**，其余属以下两类，无需改：

| 卡 | 情况 |
|---|---|
| 15231 进攻美国 / 16300 火炬行动 / 17527 / 17533 | 已用 `spacesFn` 或 `around`（动态） |
| 15349 / 17722 / 17724 | 卡面"相邻"是**前提条件**（"若相邻没有英国陆军"），不是候选范围 |
| 17524 进击的巴顿 | 第 2 步 `battle` 用 `useNewPiece`，"相邻"由刚建单位所在格动态算 |
| 15350 奇袭塔兰托 | `eliminate(地中海)` 就是卡面写死的地（"在<地中海>消灭"） |
| 17823 千岛群岛登陆行动 | `battle(日本)` 是卡面明确的目标地区 |

**教训**：卡面写"相邻"就应动态算（`spacesFn` / `around`），写死地区名会随地图数据变动静默漏项。

## 六、回修入口

| 症状 | 先看 |
|---|---|
| 某"相邻地区"卡少了某个地区 | 该卡 `steps` 是否用了固定 `spaces`；改用 `spacesFn` 动态算 |
| 候选含不该有的地区 | `spacesFn` 是否加了地形/阵营过滤 |
| 候选为空导致卡打不出 | `event_card_needs` 返回 null 时的兜底文案（"没有合法目标"） |
