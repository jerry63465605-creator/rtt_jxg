## 2. 类型确认：↑ = 增强卡

像素分析（`tools/analyze_icons.ps1`）与 GLM 读图**双确认**：
8 张右上角均为 **↑ 单箭头**。

对照 `docs/card-icons.md`：

| 图标 | 类型 |
|---|---|
| `↑` | **增强卡 ECHO**（code = `EFFECT`） |
| `!` | 事件卡 EVENT |
| `?` | 响应卡 RESPONSE |
| `⇈` | 状态卡 STATUS |

**命名说明**：`docs/card-icons.md` 记作 `ECHO`，
代码 code 用 `EFFECT`（历史原因），二者指同一类型。
`CARD_TYPE_INFO.EFFECT` 描述已修正为
“增强卡：在对应时机打出，置入弃牌堆并执行效果；**不占**出牌名额”。

## 3. 语义：与事件卡的核心差别

| | 事件卡 EVENT | 增强卡 ECHO |
|---|---|---|
| 图标 | `!` | `↑` |
| 打出时机 | 出牌阶段 | **自己回合的对应阶段** |
| **占出牌名额** | **是** | **否** |
| 打出后 | 进弃牌堆 | 进弃牌堆 |

两者**共用同一套执行器**（`card_effect_of` 分发 + `resolve_event_card`），
差别**只在时点与名额**。

> **“涉及阶段的时机都是自己回合”** —— 玩家 2026-09-25 明确。
> 详见 `docs/triggers.md` §2。

## 5. 两个新增 op

### `protect`（15311 马奇诺防线）

```javascript
{ op:'protect', nation:'法国', types:['army'], spaces:[6], until:'turn' }
```

走统一修正器注册表 `game.modifiers`，
判定入口 `is_protected()`，由 `resolve_supply()` 调用。

- 只保护：**法国** + **陆军** + **西欧**
- 到期：`until:'turn'`，回合推进时 `prune_modifiers` 清掉
- 被跳过的部队记在 `resolve_supply.last_protected`

### `peek_reorder`（15305 双十字系统）

```javascript
{ op:'peek_reorder', target:'德国', count:2 }
```

两步交互：

1. 随机挑 2 张德国手牌 → `game.peek`，返回 `pending` 等玩家
2. 玩家提交 `arg.order = [A, B]` → 从德国手牌移除，
   按 `order` 压到德国**牌堆顶**（`order[0]` 在最顶）

校验：`order` 排序后必须与挑出的牌一致，否则拒绝。

> ⚠️ **UI 待办**：第 2 步需要界面选牌并排序，
> 目前服务端逻辑完整，客户端交互尚未实现。

## 6. 与 EVENT 共享底层

```
ECHO_EFFECTS  ─┐
               ├─> card_effect_of() ─> resolve_event_card() ─> 原子操作层
EVENT_EFFECTS ─┘                                                (build/recruit/
                                                                 eliminate/battle/
                                                                 grant_supply)
```

新增卡只需加一条配置，底层逻辑（建设/征召/消灭/战斗/补给）
**一律复用，不重复实现**。详见 `docs/event-cards.md` §1 分层架构。
