## 1. 规则原文（easy_rule 二章）

> **二、回合**
>
> 1. 资源再分配：可以执行以下操作
>    - 弃 3 张手牌，从牌堆中挑选 1 张基本卡置入手牌，然后洗混牌堆
> 2. 出牌阶段：必须执行下列其中之一
>    - 打出 1 张手牌
>    - 弃置 1 张手牌
>    - 减 1 分
> 3. 空军阶段：可以执行下列其中之一
>    - 打出【空军力量】
>    - 弃 1 张手牌，调度 1 支空军
> 4. 补给阶段：将当前回合者不处于补给状态的部队移除
> 5. 计分阶段：计算当前回合者的胜利得分（大本营被敌方军队占领则跳过）
> 6. 弃牌阶段：可以弃任意数量的手牌
> 7. 摸牌阶段：将手牌摸至 7 张，除非牌堆被摸空
>
> 游戏按照以下国家顺序进行：**德国 → 英国 → 日本 → 苏联 → 意大利 → 美国**

**「一个回合」= 6 个国家各完整执行一次上述 7 阶段。**

## 2. 结构性问题：2 个 role vs 6 个国家

这是本项目最关键的架构张力，必须理解：

| 层面 | 数量 | 来源 |
|---|---|---|
| RTT 玩家位（role） | **2** | `exports.roles = ['Axis','Allies']` —— 决定谁能提交动作 |
| 行动顺序国家 | **6** | 规则书的德英美日苏意 —— 决定谁在行棋 |

规则书要求「按国家顺序进行」，但 RTT 只允许 2 个 role 提交动作。
**解法**：`current_nation` 驱动的"代表制"。

```javascript
/*
 * RTT 的 role -> 该玩家位当前"代表"的国家。
 * 轮到谁，控制该阵营的玩家就看谁的手牌、替谁决策。
 */
function nation_of_player(game, role) {
    const n = game.current_nation
    const f = faction_of_nation(n)
    if (role === 'Allies' && f === 'allies') return n
    if (role === 'Axis'   && f === 'axis')   return n
    return null      // 非本方回合：不给手牌
}
```

**效果**：
- 德国回合 → 轴心玩家行动、看到德国手牌；同盟玩家 `my_nation = null`，只看到张数
- 英国回合 → 同盟玩家行动、看到英国手牌
- 意大利回合 → 又轮到轴心玩家（意大利属轴心）

**action 的归属校验交给 RTT**：服务器用 `state.active` 与提交者 role 比对，
我们只需保证 `game.active` 在阵营切换时正确轮转。

## 3. 状态机实现

### 3.1 state 字段

```javascript
{
  turn: 1,                       // 回合数
  active: 'Axis',                // RTT role（决定谁能提交）
  current_nation: '德国',        // 行动顺序国家（决定谁在行棋）
  turn_phase: 'resource',        // 7 阶段之一
  nations_done: 0,               // 本回合已轮过的国家数（0..5）
  play_done: { 德国: false },    // 出牌阶段"三选一"是否已用（v1.1 取代 action_points）
  ask_remove: {},                // 收回部队询问开关（按阵营，默认关闭）
  pending_ask: null,             // 待处理的"友方出牌回合开始"收回询问
  phase_note: '...',             // 当前阶段的提示（供 UI）
  last_supply: { ... },          // 上次补给结算结果
}
```

### 3.2 阶段推进

```javascript
advance_phase(game)
  ├─ 还有后续阶段 -> turn_phase = 下一阶段，执行其入口逻辑
  └─ 7 阶段跑完  -> 轮转到下一国家
                    └─ 6 国跑完 -> turn++，active 在两 role 间交替
```

**入口逻辑**（进入阶段时自动执行的部分）：

| 阶段 | 自动执行 |
|---|---|
| resource | `phase_resource()` —— **清零该国资源再分配计数**（每回合各一次）；弃 3 张挑 1 张需玩家决定 |
| play | `play_done[nation] = false`；并按开关准备"收回部队"询问 |
| airforce | 仅提示（调度需玩家决定） |
| supply | `resolve_supply(game, nation)` —— 移除该国断补部队 |
| scoring | 判定大本营是否被占 → 加分或跳过 |
| discard | `enforce_hand_limit(game, nation)` —— 弃到 7 张 |
| draw | `draw_cards(game, nation, 2)` |

### 3.3 已确认口径

| # | 问题 | 决定 |
|---|---|---|
| 1 | 补给结算范围 | 只结算**当前行动国**的部队（德国回合不管意大利部队） |
| 2 | 大本营被占领的判定 | 该国大本营格位上**有敌方部队**即跳过计分 |
| 3 | 空军阶段 | 可调度空军；部署/夺取制空权需卡牌驱动 |
| 4 | 前奏 | 不实现，直接从第 1 回合开始 |
| 5 | 出牌阶段 | **每回合三选一（打出/弃置/减 1 分）只做一次**，无行动点 |
| 6 | 无可打出且无法弃牌 | 只能选「减 1 分」（手牌为空时） |

## 4. 手牌模型

### 4.1 数据结构

每国独立五区（规则：每国有自己的牌堆）：

```javascript
{
  decks:   { 德国: [card_id...] },   // 抽牌堆
  hands:   { 德国: [card_id...] },   // 手牌（暗牌）
  discard: { 德国: [card_id...] },   // 弃牌堆
  table:   { 德国: [card_id...] },   // 桌面上持续生效的状态/效果卡
  removed: { 德国: [card_id...] },   // 移出游戏（第 6 回合后的基础卡）
  shuffle_count: { 德国: 1 },        // 重洗次数（保证确定性）
}
```

### 4.2 确定性洗牌（RTT 的硬要求）

RTT 依赖**重放**来重建状态，任何随机都必须可复现。
所以不能直接用 `Math.random()`：

```javascript
shuffle_deterministic(arr, seed)   // xorshift32，基于 seed + 国家散列
```

**关键**：种子 = `game.seed + nation_hash(nation)`，
保证 ① 同种子结果一致；② 各国洗牌顺序不同（否则所有国家手牌一样）。

重洗时用 `game.seed + shuffle_count + nation_hash`，同样可复现。

### 4.3 暗手牌

```javascript
hand_view(game, nation, viewer_nation) {
    count: 张数（公开）
    cards: viewer_nation === nation ? 牌面 : null   // 只有本人看得见
}
```

view 对**对手**只输出张数，不泄漏牌面。

## 5. 动作清单

| action | 阶段 | 说明 |
|---|---|---|
| `next_phase` | 任意 | 推进到下一阶段 |
| `resource_swap` | resource | 弃 3 张手牌挑 1 张基本卡，然后洗混牌堆 |
| `play_card` | play | ① 打出 1 张手牌；状态/效果卡留置桌面 |
| `discard_one` | play | ② 弃置 1 张手牌 |
| `minus_score` | play | ③ 减 1 分（本方阵营总分 −1） |
| `air_support` | airforce | 调度空军：弃 1 张手牌，移到本国陆军/海军所在地 |
| `remove_piece` | 任意（本国回合内） | 收回 1 支本国部队（棋子回池） |
| `toggle_ask_remove` | 任意 | 开关"友方出牌回合开始的收回询问"（默认关闭） |
| `clear_ask` | 任意 | 跳过当前的收回询问 |

①②③ 共用 `play_done[nation]`，同一出牌阶段只能成功一个。

调试动作：`debug_place` / `debug_remove` / `debug_clear` / `debug_draw` /
`resolve_supply` / `next_nation` / `log`

### 8.1 计分阶段的临时实现

规则原文是「获得计分标记的分数」，但"计分标记"来自建设/征召系统
（建设军队 => 在该国得分记录轨增加标记）。这在建设系统做好前无法精确实现。

**当前近似**：得分 = 该国**处于补给状态**的部队数。

这是**有意为之的占位**，不是最终规则。建设系统接入后应替换
`phase_scoring()` 的实现。

### 8.2 开发期卡组兜底

只有英国卡组已编译。为让其余 5 国能跑通回合流程，
`rules.js` 里有个开关：

```javascript
const USE_TEST_DECKS = true   // 无卡组的国家借用英国卡组代打
```

补全各国卡组后**必须关闭**。日志里会打印
`（开发期）意大利 暂用英国卡组代打` 以提示。
